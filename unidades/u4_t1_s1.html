Subtema 1.1: Tipos de pruebas de software (Funcionales y No Funcionales)

← Volver al Índice

El objetivo de las Pruebas

Las pruebas o tests son el mecanismo para evidenciar que el software se comporta como se espera y cumple con lo especificado por el cliente. Es importante recordar que no es posible garantizar la ausencia total de defectos, solo se prueba una parte de los infinitos usos posibles.

Pruebas Funcionales (Caja Negra)

Se enfocan en qué hace el sistema. Se verifica el comportamiento externo sin conocer la implementación interna.

  • Basadas en el documento SRS (Software Requirement Specification).
  • Foco en usabilidad y requisitos del cliente.
  • Herramientas clave: Diagramas de Casos de Uso.

Pruebas de Caja Blanca

Se enfocan en cómo lo hace. Permiten analizar el diseño, la estructura interna e incluso el código fuente.

  • Buscan optimizar el rendimiento y seguridad.
  • Requieren conocimientos de programación.
  • Evalúan flujos lógicos y cobertura de sentencias.

Pruebas No Funcionales

Se enfocan en factores transversales relacionados con la experiencia del usuario y capacidades del sistema. Generalmente son sugeridas por el equipo técnico.

Usabilidad
Seguridad
Rendimiento / Carga
Accesibilidad
Escalabilidad
Mantenibilidad

Pruebas Grises o de Humo (Smoke Test)

Determinan la estabilidad de una compilación. Si esta prueba falla, no tiene sentido seguir adelante con el resto de las pruebas detalladas, ya que el sistema no es lo suficientemente estable.

Ejemplo: Registro de Usuario (Caja Negra)

Para un requerimiento como "El sistema permitirá el registro", la prueba define entradas y salidas sin mirar el código:

Entrada: Nombre, Apellidos, Correo, Contraseña.
Proceso: (Desconocido por ser caja negra).
Salida: Mensaje "El usuario ha sido registrado".
